## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, repository import, worker CLI or subprocess. Section 2 is `src/swin_classification_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 2-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins (`torch==2.14.0`, `torchvision==0.29.0`, `torchaudio==2.11.0`, `timm==1.0.28`, `huggingface-hub==0.36.2`, `safetensors==0.8.0`, `pillow==12.3.0`). `metadata.dimer.generated_from` records the repository, the module's last commit, its SHA-256, and the generator version. The `GITHUB_TOKEN` fallback of the previous revision is gone: nothing is cloned.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent (`config.json`, `model.safetensors`), from the Hugging Face Hub at the immutable revision `650d02aabf05e8adbd060a739ab39e39f53da639` (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=WEIGHTS_DIR)` binds the verified checkpoint (the network is built at fit time with a fresh head; timm executes no remote model code; `pretrained=False` + `safetensors` load, never `torch.load`).
- **In-kernel fine-tuning (kept from the previous revision):** `validate_dataset` writes the DIMER handoff (`logical-dataset-manifest.json`, `data-plan.json`, `semantic-dataset-schema.json`, `validated-dataset-manifest.json`, evidence layers, `result.json`) with the pinned validator worker release digest; `pipe.fit` requires `cuda:0` (**no silent CPU fallback**), trains all parameters with AdamW/cross-entropy, publishes the artifact generation (per-member SHA-256, `bundleDigest`, `model_manifest.json` for `dimer-inference-service-timm`), and reports metrics from the **reloaded** artifact. Seeds are explicit (`SAMPLE_SEED`, `SEED`); the run manifest records `reproducibility: REEXECUTABLE`; the notebook states that bitwise-identical results across GPUs are not promised.
- **Fresh-boundary verification (VER1–VER8):** `SwinClassificationPipeline.from_artifact` on a copied generation re-verifies every member digest, rebuilds the network from `model-config.json` alone, loads `model.safetensors` with `strict=True`, and `evaluate_split` re-scores the frozen validation split; accuracy must equal the reported value exactly and cross-entropy within `1e-4`, else the notebook stops.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/swin_classification_input_manifest.json` with the schema, ceilings (`MIN_CLASSES`, `MAX_EXPANDED_BYTES`, `INPUT_SIZE`, accepted extensions), per-dataset observations (classes, split counts, `logicalDatasetDigest`), non-fatal validator warnings as findings, and one recorded rejection finding from a stray-root-file probe; `evaluation_report` (EVAL21) writes `outputs/swin_classification_evaluation_report.json` — `sample-sanity` with accuracy and cross-entropy on the single frozen holdout, the data-derived majority baseline and the reload check; `not-measurable` when no validation split was scored.
- The default sample is a deterministic synthetic two-class set (24 PNGs) drawn in code by `generate_synthetic_sample` (no download). Its metrics are sanity evidence for the plumbing, not ImageNet or production evidence. The jittered generator can emit byte-identical images in two splits; the validator reports that as the non-fatal `VISION_DUPLICATE_CONTENT_ACROSS_SPLITS` warning, carried into the input manifest.
- Classification obligations (Notebook Specification §20.1): the class floor is printed before the model runs, the decision rule is `argmax`, softmax scores are described as uncalibrated (no threshold is shipped), and the exported per-sample CSV keeps the `classOrder` in its `score_<class>` columns.
- **BYOD (DAT7–DAT14):** `USE_BYOD` accepts one ZIP laid out as `train/<class>/`, `val/<class>/` (optional `test/`); `safe_extract_zip` rejects absolute paths, `..` traversal, symlinks, root escapes and archives above `MAX_EXPANDED_MIB`, member by member (never `extractall`). `USE_BYOD_IMAGE` accepts a single new image. Both default to `False` so the sample path never opens an upload dialog; an executor supplies `BYOD_ZIP_PATH` / `BYOD_IMAGE_PATH` instead.
- `tools/validate_release_assets.py` performs source validation only (`scripts/validate_colab_tutorial.py` delegates to it). It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
